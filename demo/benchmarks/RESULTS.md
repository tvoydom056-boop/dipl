## Замечание

Текущие bundle-метрики относятся к demo-приложению целиком для каждой отдельной реализации, а не к "чистому" размеру самих библиотек в изоляции.
Отдельный замер `kiks runtime package` показывает размер уже самой библиотеки, а не demo-приложения.
Это позволяет честно разделять две метрики:

1. размер прикладного стенда на конкретной реализации;
2. размер публикуемой библиотеки как npm-пакета.

Показатель `re-render` теперь тоже формируется автоматически, но его нужно интерпретировать как benchmark логических UI-зон и React commits в одинаковом общем интерфейсе, а не как прямой экспорт значений из браузерного DevTools.

## Selector strategies benchmark

Сценарий: исследование четырёх вариантов реализации `Selector` в ядре `kiks` на одинаковом наборе операций: первый вызов, повторный вызов на том же состоянии, вызов после несвязанного изменения `state` и вызов после связанного изменения фильтра/поиска.

| Стратегия            | First run, ms | Repeat run, ms | Unrelated change, ms | Related change, ms | Stable snapshot |
| -------------------- | ------------: | -------------: | -------------------: | -----------------: | --------------: |
| Full recompute       |        0.3343 |         0.3169 |               0.3050 |             0.3171 |              0% |
| Last-result cache    |        0.3074 |         0.0004 |               0.2978 |             0.3292 |              0% |
| State reference memo |        0.3521 |         0.0001 |               0.3250 |             0.3315 |              0% |
| Dependency memo      |        0.3501 |         0.0013 |               0.0008 |             0.3119 |            100% |

### Математические методы выбора

- `AHP` используется для фиксации весов критериев:
  - first run `0.08`
  - repeat run `0.22`
  - unrelated change `0.22`
  - memory efficiency `0.08`
  - implementation simplicity `0.10`
  - integration ease `0.10`
  - rerender stability `0.20`
- Взвешенная сумма дала первое место `Dependency memo` со score `6.804`.
- `TOPSIS` дал первое место `Dependency memo` со score `8.368`.
- Метод Парето не исключил стратегии полностью, но показал, что `Dependency memo` остаётся в эффективном фронте и выигрывает по совокупности критериев устойчивости и производительности.

### Вывод по Selector

Для финальной реализации `Selector` в `kiks` выбран подход `Dependency memo`, потому что он:

1. почти не проигрывает в первом вызове;
2. резко ускоряет вызовы после несвязанных изменений состояния;
3. сохраняет ссылочную стабильность результата и тем самым лучше подходит для `useSyncExternalStore`;
4. естественно встраивается в архитектуру явных selector-зависимостей.
